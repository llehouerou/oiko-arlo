# AGENTS.md

- Everything committed to this repo is written in English: code, comments, docs, commit messages, and test data too (names of devices, rooms and locations in fixtures and tests).
- This repo is public: never commit personal data. No real names of people, addresses or coordinates of a real home, its time zone, host names, IP or MAC addresses, device serials or IDs, Arlo account identifiers (emails, user, location or device IDs), passwords, tokens, session files or other secrets, and no recording from the real account (go-arlo dumps, HTTP responses, MQTT messages) unless every identifier and name in it has been replaced with made-up ones. Test data uses made-up names and IDs (House, Gate, Veranda, BASE, CAM1, `oiko@example.com`).
- This module is the `arlo` type of Bridge of [Oiko](https://github.com/llehouerou/oiko). It imports only Oiko's public `bridge` package (Oiko's ADR 0017) and speaks Oiko's vocabulary (its `GLOSSARY.md`): Bridge, Device, Function, Capability, Native Address, Availability. Oiko's ADR 0010 records why Arlo goes through go-arlo, and how the location's mode is carried by the base station.
- The root package registers the type: `oiko-build` and the catalogue (Oiko's ADR 0020) import it alone. `oiko-bridge.json` describes each type it registers; `TestManifest` keeps the two in step with `Config`.
- This is the reference type for cameras and Recordings that Oiko's guide (`docs/write-a-bridge.md`) links: keep it as its sample, `docs/write-a-bridge/plug/`, shows. Every test that runs the Bridge does so through `bridgetest`, inside `synctest.Test`, with no real clock or network (S3 is the in-memory `network`). `go vet` and `gofmt` stay clean.
- The session stays `session.json` in the Bridge's data directory, used by one instance only. Never add a retry around go-arlo's login: Arlo rate limits auth attempts with a long cooldown.
- Releases follow Oiko's ADR 0019 as it applies to a type of Bridge: during v0, a patch neither breaks nor adds anything (configuration keys, Functions, Capabilities, the session file), a minor may break the configuration and its release notes list each change. Raising the required Oiko to a new minor is a minor here too; each Oiko minor release ends with this repo moved to it and tagged. Releases are tags `vX.Y.Z` on `main`, after `go test ./...` passes.
- Issues live in GitHub Issues (llehouerou/oiko-arlo), via `gh`.
